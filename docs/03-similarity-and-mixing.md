# 03. Схожість і міксування

## Головна ідея

Схожість тут — **не одна відстань між векторами**. Діджей не питає
"який трек найбільш схожий", він питає "який трек сюди ляже". Це два
різних питання, і друге вирішується двоетапно:

```
1. ФІЛЬТР (жорсткий)   → темп сумісний? тональність сумісна?
2. СКОРИНГ (м'який)    → наскільки схожий тембр, як лягає енергія?
```

Одновекторний ANN-пошук провалює саме перший етап: він радо віддасть
трек із ідеальним тембром на 92 BPM, коли грає 128. Тому pgvector у нас
рахує тільки тембровий компонент, а темп і тональність — звичайні
SQL-предикати.

## Етап 1: фільтр

### Темп

Time-stretch на ±6% людське вухо не помічає (артефакти rubberband
починаються приблизно там). Тому:

```
сумісні, якщо |bpm_b - bpm_a| / bpm_a <= 0.06
```

**Але треба врахувати октави.** Трек на 70 BPM і трек на 140 BPM
міксуються прекрасно — половинний темп. Тому кандидат проходить, якщо
підходить будь-яке з: `bpm_b`, `bpm_b * 2`, `bpm_b / 2`.

```sql
WHERE bpm BETWEEN :lo AND :hi
   OR bpm BETWEEN :lo*2 AND :hi*2
   OR bpm BETWEEN :lo/2 AND :hi/2
```

Треки з `bpm_confidence < 0.5` виключаємо з beat-aligned пошуку взагалі —
для них окремий режим "довгий фейд".

### Тональність — Camelot wheel

Camelot — це коло квінт, перенумероване так, щоб сумісність рахувалася
арифметикою. 1–12 по колу, `A` = мінор, `B` = мажор.

```
Мажор:  C=8B  G=9B  D=10B A=11B E=12B  B=1B
        F#=2B Db=3B Ab=4B Eb=5B Bb=6B  F=7B
Мінор:  Am=8A Em=9A Bm=10A F#m=11A C#m=12A G#m=1A
        Ebm=2A Bbm=3A Fm=4A Cm=5A Gm=6A Dm=7A
```

Правила сумісності (від найкращого):

| Перехід | Правило | Ефект |
|---|---|---|
| Той самий | `8A → 8A` | ідеально, нудно |
| Відносний | `8A → 8B` | зміна настрою мінор/мажор, дуже сильний хід |
| ±1 по колу | `8A → 7A` або `9A` | плавно, найчастіший діджейський хід |
| +2 (energy boost) | `8A → 10A` | помітний підйом енергії |
| +7 / інше | — | дисонанс, тільки якщо один трек уже майже стих |

```python
def camelot_distance(a: str, b: str) -> int:
    """0 = ідеально, 1 = добре, 2 = прийнятно, 99 = не міксувати."""
    na, ma = int(a[:-1]), a[-1]
    nb, mb = int(b[:-1]), b[-1]
    step = min((na - nb) % 12, (nb - na) % 12)
    if na == nb and ma == mb:  return 0
    if na == nb and ma != mb:  return 1   # відносний
    if step == 1 and ma == mb: return 1
    if step == 2 and ma == mb: return 2   # energy boost
    return 99
```

Треки з `key_confidence < 0.4` пропускаємо через фільтр завжди —
краще не заважати, ніж заважати на основі поганої оцінки.

## Етап 2: скоринг

```python
score = (
    0.45 * timbre_similarity      # cosine на timbre_vec, [0..1]
  + 0.20 * band_similarity        # cosine на band_vec
  + 0.15 * harmonic_bonus         # 1 - camelot_distance/3
  + 0.10 * tempo_closeness        # 1 - |Δbpm|/(0.06*bpm)
  + 0.10 * energy_fit             # наскільки лягає в цільову криву
)
```

Ваги — стартові, підбирати вухом. Заведи їх у конфіг, а не в код:
ти будеш крутити їх десятками разів.

`energy_fit` — єдиний компонент, який залежить не від пари треків,
а від **позиції в сеті**. Це те, що відрізняє плейлист від сету.

### Крива енергії сету

```
енергія
  ▲
  │              ╭──────╮
  │          ╭───╯      ╰───╮
  │      ╭───╯              ╰──╮
  │  ╭───╯                     ╰────
  └──┴────────────────────────────────▶ час
    warmup    build   peak    cooldown
```

Задаємо як функцію `target_energy(position_fraction) → [0..1]`.
Кілька пресетів: `linear_rise`, `classic_arc` (як вище), `flat`,
`descending`. `energy_fit = 1 - |track_energy - target|`.

`track_energy` беремо як нормалізовану комбінацію RMS-медіани,
spectral centroid і щільності онсетів — не просто гучність.

### Побудова сету (жадібний алгоритм)

```
1. Взяти seed-трек, покласти в сет.
2. Поки сумарна тривалість < цільової:
   a. кандидати = фільтр(останній трек) мінус уже використані
   b. для кожного порахувати score з урахуванням target_energy
      на наступній позиції
   c. взяти топ-5 і вибрати випадковий зважений (щоб сет не був
      детермінованим і нудним)
   d. додати в сет
3. Якщо кандидатів немає — послабити фільтр темпу до ±10% і
   спробувати ще раз; якщо все одно немає — завершити сет.
```

Жадібний алгоритм не дає оптимального сету, але дає **добрий за
мілісекунди**. Beam search (тримати 10 найкращих часткових сетів)
покращує результат помітно і коштує дешево — зроби на M3, не раніше.

## Міксування

### Вибір точок переходу

Це те місце, де проект або звучить добре, або звучить як аматорський
crossfade. Алгоритм:

```
1. Кандидати виходу з треку A:
   межі сегментів у останній третині треку,
   що збігаються з downbeat, пріоритет — початок 'outro'.

2. Кандидати входу в трек B:
   межі сегментів у першій третині,
   пріоритет — початок 'intro' або перший downbeat після нього.

3. Довжина переходу: 16 або 32 біти (не секунди!).
   На 128 BPM 32 біти = 15 секунд.

4. Обмеження: точка виходу має бути мінімум за (довжина переходу)
   до кінця A, і не раніше 60% тривалості A.
```

Ключове: **міряти перехід у бітах, не в секундах.** Перехід, що
починається й закінчується на межі фрази, звучить навмисним. Перехід
на 12.5 секунд звучить як помилка.

### Beat alignment

```python
# 1. Цільовий темп переходу — темп A (або середнє, якщо різниця мала)
ratio = bpm_a / bpm_b
# 2. Розтягнути B у часі без зміни висоти
b_stretched = pyrubberband.time_stretch(y_b, sr, ratio)
# 3. Зсунути так, щоб downbeat B збігся з downbeat A
offset = downbeat_a_at_mix_point - downbeat_b_at_in_point * ratio
```

`pyrubberband` (обгортка над rubberband CLI) — якісніше за
`librosa.effects.time_stretch` на музиці. Потребує встановленого
`rubberband-cli`. Для ±6% різниця чутна.

### Крива crossfade

**Не лінійна.** Лінійний фейд дає провал гучності на -3 дБ посередині,
бо два некорельованих сигнали складаються по потужності, а не по
амплітуді. Правильна — рівнопотужна:

```python
t = np.linspace(0, 1, n_samples)
fade_out = np.cos(t * np.pi / 2)
fade_in  = np.sin(t * np.pi / 2)
# fade_out² + fade_in² == 1 на всій довжині
```

### EQ-swap (bass swap) — обов'язково, не опційно

**Проблема.** У низах живе ~80% енергії треку. Коли під час переходу
грають дві бочки і дві бас-лінії одночасно, вони складаються по
потужності, але не по фазі: виходить бубоніння, каша, і лімітер
душить увесь мікс. Рівнопотужний фейд це не рятує — він правильно
тримає сумарну гучність, а проблема не в гучності, а в тому, що
низ став некорельованою сумою.

**Рішення.** Ввести трек B **без басу** — чутно його верхи, мелодію,
хети поверх A. Потім у конкретний момент **на долі** миттєво зняти
бас з A і віддати його B. Низ «перестрибує» з треку на трек за один
біт. Мікс лишається чистим і панчовим, а сам момент підміни звучить
як навмисний ефект — це те, що вухо впізнає як «діджей», а не
«плейлист».

```
   гучність
        │  A_high ────╮
        │             ╰────╮
        │  B_high  ╭───────╯────────
        │       ╭──╯
        ├───────────────┬────────────  A_low  (обрив на swap point)
        │               ╰──╴
        │               ╭──╴
        └───────────────┴────────────  B_low  (вступ на swap point)
          ▲                          ▲
       початок                    кінець
       переходу      ▲ swap point (downbeat)
```

**Реалізація.** Не намагайся інтерполювати коефіцієнти фільтра на
льоту — це джерело артефактів. Розділи кожен трек на дві смуги
**один раз**, а далі працюй звичайною автоматизацією гучності:

```python
from scipy.signal import butter, sosfilt

def lr4_split(y, sr, fc=150.0):
    """Linkwitz-Riley 4-го порядку = два каскади Butterworth 2-го."""
    lp = butter(2, fc, btype='low',  fs=sr, output='sos')
    hp = butter(2, fc, btype='high', fs=sr, output='sos')
    low  = sosfilt(lp, sosfilt(lp, y))
    high = sosfilt(hp, sosfilt(hp, y))
    return low, high

a_low, a_high = lr4_split(y_a, sr)
b_low, b_high = lr4_split(y_b, sr)

# верхи — звичайний рівнопотужний фейд на всю довжину переходу
out_high = a_high * fade_out + b_high * fade_in

# низи — різкий обмін у swap point
out_low  = a_low * swap_out + b_low * swap_in

out = out_low + out_high
```

**Чому саме Linkwitz-Riley 4-го порядку.** LP і HP цієї схеми
складаються назад у плоску АЧХ (allpass по фазі, рівна амплітуда).
Butterworth 2-го порядку дав би на кросовері горб +3 дБ, і кожен
трек, пропущений через розділення, звучав би не так, як оригінал.
Практично LR4 = двічі застосований Butterworth 2-го порядку.
`sosfilt`, не `sosfiltfilt` — filtfilt подвоює порядок і ламає
властивість складання.

**Параметри, які варто крутити:**

| Параметр | Старт | Про що |
|---|---|---|
| Частота кросоверу | 150 Гц | Нижче 100 — бочки лишаються удвох. Вище 250 — з басом їде тіло інструментів, чутно як «телефон» |
| Swap point | 50–66% переходу, найближчий downbeat | На початку — B ще не встиг зайти; в кінці — A вже майже нема, ефект пропав |
| Довжина самого обміну | 1 біт | Миттєвий обмін дає клац/удар. Один біт — достатньо гладко і все ще різко |
| Крива обміну | рівнопотужна | Та сама `cos/sin`, просто на коротшому відрізку |

**Варіант для зв'язки з drop'ом:** якщо в треку B перший downbeat
після `intro` — це вхід у `drop`, поставити swap point рівно туди.
Тоді бас B з'являється разом із його дропом, і перехід звучить так,
ніби так і було задумано. Це найдешевший спосіб зробити мікс схожим
на людський: одна умова у виборі swap point.

**Валідація:** побудуй спектрограму переходу і подивись на смугу
20–150 Гц. Не має бути жодного відрізка, де там енергія обох треків
одночасно. Якщо є — swap point не збігся з downbeat.

### Вирівнювання гучності

Перед склейкою кожен трек нормалізується до **-14 LUFS**:

```python
loudness = meter.integrated_loudness(y)
y = pyln.normalize.loudness(y, loudness, -14.0)
```

Потім перевір true peak — після нормалізації можливий клippінг.
Ліміт на -1 dBTP.

### Рендер

```
render_mix(set) -> wav
  для кожної пари (A, B):
    завантажити A і B у повній якості (44.1/48 kHz stereo)
    нормалізувати гучність
    time-stretch B
    порізати, застосувати EQ-swap і рівнопотужний фейд
    накласти в спільний буфер за розрахованими зсувами
  записати wav (float32 → 24-bit)
```

Пиши у WAV, не в MP3 — це проміжний артефакт, перекодуєш потім, якщо
захочеш. Мікс на годину у 48kHz/24bit stereo — ~1 ГБ. Нормально.

## Жанрові відмінності

Основний матеріал — електроніка. Це найзручніший випадок, і майже все
вище написано під нього. Рок додасться пізніше, і він ламає три
припущення — краще знати заздалегідь, щоб не закласти їх намертво.

| | Електроніка | Рок / живі записи |
|---|---|---|
| Темп | постійний, квантований | плаває на 1–3% у межах треку |
| Бітова сітка | `first_beat + n/bpm` — точно | тільки масив реальних бітів |
| Структура | чіткі 8/16/32-тактові фрази | фрази нерівні, буває 6 або 10 тактів |
| Тональність | часто один акорд/лад весь трек | модуляції, дисторшн псує хрому |
| Точка входу | `intro` майже завжди чистий | часто одразу гітара + вокал |

**Три правила, які варто закласти зараз, навіть поки грає тільки
електроніка:**

1. **Ніколи не рахуй позицію біта з BPM.** Завжди бери значення
   з масиву `beats` у `.npz`. У треку з постійним темпом результат той
   самий, у живому — різниця в кінці треку до півсекунди. Це один
   рядок різниці в коді і врятує повне переписування на M7.

2. **Time-stretch глобальним коефіцієнтом коректний тільки для
   постійного темпу.** Для живого запису розтягнення на 4% у
   середньому означає, що на початку переходу біти зійшлися, а на
   кінці розповзлись. Ознака — `bpm_confidence`: при значенні нижче
   ~0.6 не розтягуй узагалі, а зроби довгий фейд без beat-alignment.

3. **Вага тональності у скорингу має залежати від
   `key_confidence`.** Хрома на дисторшн-гітарі — це майже шум,
   і `camelot_distance` на її основі дасть впевнено неправильну
   відповідь. Формула: `harmonic_weight = 0.15 * min(conf_a, conf_b)`.

Плюс одна практична річ: у рок-треку немає `drop`, тому евристика
лейблів сегментів має мати запасний варіант — якщо максимум енергії
не в середній третині, лейбли `intro / verse / chorus / outro`
за чергуванням енергії, а не за абсолютним максимумом.

## Стратегії міксу — розширюваність

Заклади інтерфейс одразу, навіть якщо реалізація одна:

```python
class MixStrategy(Protocol):
    def choose_points(self, a: Track, b: Track) -> TransitionPlan: ...
    def render(self, a: np.ndarray, b: np.ndarray,
               plan: TransitionPlan) -> np.ndarray: ...

class SimpleCrossfade(MixStrategy):   # M3
class EqSwapCrossfade(MixStrategy):   # M3
class LoopRollTransition(MixStrategy) # пізніше
class LlmDirectedMix(MixStrategy)     # "ІІшка"
```

### Що реально може дати ІІ

Не варто уявляти, що модель «зробить мікс». Реалістичні застосування,
за зростанням складності:

1. **Вибір стратегії.** Подати LLM опис пари треків (жанрові теги,
   енергія, структура, ключ) і список доступних стратегій — хай
   вибере і поставить параметри. Дешево, працює, дає різноманіття.
2. **Тегування бібліотеки.** Прогнати треки через
   CLAP / MusicFM / OpenL3 і отримати ембедінги, навчені на музиці,
   а не на MFCC. Такий ембедінг ловить "жанр" і "настрій" значно краще
   за спектральні дескриптори — і підключається просто як ще один
   вектор у `track_features`.
3. **Source separation.** `demucs` розкладає трек на drums/bass/other/
   vocals. З цим стає можливим справжній stem-мікс: бас від A + вокал
   від B. Це найцікавіше, що можна зробити в проекті, і найважче.
4. **Навчена модель точок переходу.** Потрібен датасет реальних
   діджейських сетів із розміткою. Практично недосяжно для пет-проекту.

Порядок такий не випадковий: (2) дасть найбільший приріст якості
підбору за найменших зусиль. Роби його одразу після того, як
базовий пошук запрацює.

## Валідація

- Згенеруй сет із 10 треків і **послухай цілком**. Це єдиний
  надійний тест. Записуй, де саме різонуло.
- Перевір, що на переході немає клацань — це означає розрив фази
  на межі буферів; лікується мікрофейдом 5 мс на стиках.
- Порівняй спектрограму переходу: не має бути секунди, де обидва
  треки на повному басі.
- Перевір LUFS готового міксу — має бути близько -14 по всій
  довжині, без стрибків більше 2 LU між треками.
