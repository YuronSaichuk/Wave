# Wave

Пет-проект: аналіз музики через перетворення Фур'є, автоматичний пошук
схожих треків, безшовне міксування і синхронізоване керування світлом
для домашніх міні-концертів.

## Три ключові фічі

1. **Аналіз** — розкласти трек по STFT на частотні характеристики і
   витягнути набір ознак (тембр, гармонія, ритм, енергія, структура).
2. **Схожість і мікс** — знайти в базі найближчі треки і склеїти їх
   у безперервний сет. Спочатку — beat-aligned crossfade, потім —
   розумніші переходи.
3. **Світло** — API, яке віддає світлову доріжку, синхронізовану
   з міксом, у реальне залізо (LED-стрічка, DMX) або в емулятор.

## Цільовий матеріал

Основне — **електроніка**: постійний темп, чіткі 8/16/32-тактові фрази,
чисті intro/outro. Найзручніший випадок, під нього написано все.

**Рок і живі записи** — пізніше. Вони ламають три припущення (плаваючий
темп, нерівні фрази, ненадійна хрома на дисторшні). Правила, які треба
дотриматись зараз, щоб потім не переписувати —
у [03](docs/03-similarity-and-mixing.md#жанрові-відмінності).

## Стек

| Шар | Технологія | Чому |
|---|---|---|
| Ядро аналізу/міксу | Python 3.11+ (librosa, numpy, soundfile, pyloudnorm, pyrubberband) | Готові реалізації beat tracking, chroma, MFCC. Немає сенсу писати це з нуля |
| API / оркестрація | ASP.NET Core 8 | Робочий стек, SignalR для реалтайму, швидкий UDP-вивід для світла |
| Світловий движок | .NET (Wave.Lighting) | Стабільний таймінг, UDP 40–60 FPS |
| Web UI | Angular | Знайомий стек, візуалізація спектру в браузері |
| БД | PostgreSQL + pgvector | Реляційні метадані + ANN-пошук по векторах тембру в одній базі |
| Кеш аналізу | .npz / Parquet файли на диску | Покадрові дані завеликі для рядків БД |

| `Wave — Журнал схожості` | Промахи підбору, історія зміни ваг скорингу |
| `Wave — Залізо` | Що куплено, IP стрічки, налаштування WLED, калібрування затримки |

## Головний принцип

**Усе, що можна порахувати заздалегідь — рахуємо заздалегідь.**

Мікс рендериться у файл, світлова доріжка рендериться у масив кадрів.
Під час "концерту" програма лише програє готове аудіо і шле готові кадри
по одному годиннику. Це знімає найважчу проблему проекту — реалтайм-DSP
із жорстким таймінгом — і залишає її на потім, коли (і якщо) захочеш
живий режим.
